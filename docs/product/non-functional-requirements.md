# Requisitos não funcionais

Requisitos que valem para todas as telas e para toda spec. Uma spec que toca um dos temas abaixo
cita os IDs que aplica (`NF-IN-01`, `NF-DE-07`), como já cita as decisões de design (`Dnn`).

- **Precedência:** a mesma de R3 ([`overview.md`](overview.md#requisitos-do-projeto)):
  convenções do repositório (`.claude/CLAUDE.md`) > [`decisions.md`](../design/decisions.md) >
  protótipo > handoff. Onde este documento repete uma decisão (`D09`, `D22`, `DP02`), a fonte é a
  decisão.
- **Fases:** o requisito vale para a v1 e para a V2+, salvo quando a linha diz a fase.
- **Colunas:** cada tabela tem **ID**, **Requisito**, **Como é verificado** e **Quando**. Quando
  é um destes momentos: CI; review do `reviewer`; a issue que implementa (pela letra do
  [`roadmap.md`](roadmap.md) ou pelo número); K, a verificação da v1 no build publicado.
- **Acessibilidade:** fica em [`accessibility.md`](accessibility.md) (#9). Este documento só a
  referencia (seção [Acessibilidade](#acessibilidade)).

Os IDs `NF-<TEMA>-nn` são estáveis e não colidem com `Rn`, `Dnn`, `PIn` e `DPnn`.

## Desempenho (`NF-DE`)

Metas medidas no build publicado do Pages (v1) com Lighthouse em modo mobile (perfil padrão: CPU
4x mais lenta, rede 4G lenta simulada), cache desligado, em cada uma das cinco rotas e num
`/projects/<id>` com galeria. Como o site não tem analytics (`DP02`) e não terá tráfego para o
CrUX, as metas são de laboratório, com os limites "bom" dos Core Web Vitals.
