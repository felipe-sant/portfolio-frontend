# Requisitos não funcionais

Requisitos que valem para todas as telas e para toda spec. Uma spec que toca um dos temas abaixo
cita os IDs que aplica (`NF-IN-01`, `NF-DE-07`), como já cita as decisões de design (`Dnn`).

- **Precedência:** a mesma de R3 ([`overview.md`](overview.md#requisitos-do-projeto)):
  convenções do repositório (`.claude/CLAUDE.md`) > [`decisions.md`](../design/decisions.md) >
  protótipo > handoff. Onde este documento repete uma decisão (`D09`, `D22`, `DP02`), a fonte é a
  decisão.
- **Fases:** o requisito vale para a v1 e para a V2+, salvo quando a linha diz a fase.
- **Colunas:** cada tabela tem **ID**, **Requisito**, **Como é verificado** e **Quando**. Quando
  é um destes momentos: CI; review do `reviewer`; a issue que implementa (pelo número, resumo em
  [`roadmap.md`](roadmap.md#issues-de-implementação)); #41, a verificação da v1 no build publicado.
- **Acessibilidade:** fica em [`accessibility.md`](accessibility.md) (#9). Este documento só a
  referencia (seção [Acessibilidade](#acessibilidade)).

Os IDs `NF-<TEMA>-nn` são estáveis e não colidem com `Rn`, `Dnn`, `PIn` e `DPnn`.

## Legibilidade por IA e buscadores (`NF-IA`)

**Público desta seção:** recrutador que cola a URL num chat de IA ou usa um agente de navegação,
buscadores, e prévias de link de LinkedIn, WhatsApp e Slack. Nenhum deles pode depender de
executar JavaScript.

**Problema:** a aplicação é uma SPA renderizada só no cliente. O `index.html` servido tem
`<div id="root"></div>` vazio e um `<noscript>` pedindo JavaScript. A maioria dos fetchers de IA
(os que buscam a URL que o usuário cola no chat) não executa JavaScript: para eles o portfólio é
uma página em branco com um título. O Googlebot executa JavaScript, mas em segunda passada; os
demais buscadores e as prévias de link também não executam. E, no GitHub Pages, toda rota interna
responde 404 na primeira carga (fallback por `404.html`, [`roadmap.md`](roadmap.md), M4), o que
faz crawler descartar a página.

### Pré-renderização

**Recomendação: pré-renderizar as rotas no build (SSG).** O build gera um HTML por rota pública,
por projeto, por documento de projeto e por idioma (`/pt-BR`, `/en`, `/es`), com o
conteúdo completo; no navegador o React hidrata esse HTML. Opções avaliadas:

| Opção                                                                                                                                                                                                        | Prós                                                                                                                                                       | Contras                                                                                                                                                                                                                                          | Custo estimado     | Decisão                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------ | ------------------------------------------- |
| 1. Script próprio: build SSR do Vite de uma entrada de servidor + `createStaticHandler`/`createStaticRouter`/`StaticRouterProvider` do React Router e `prerender` de `react-dom/static`, um arquivo por rota | Mantém o data router, `routes.tsx`, as páginas e as convenções; sem dependência nova; `prerender` espera `lazy` e `Suspense`, então markdown entra no HTML | Código próprio de build para manter; cuidado com hidratação (idioma, tema, dados da store serializados no HTML); confirmar como o React 19 posiciona `<title>`/`<meta>` fora de um documento completo                                            | 3 a 5 dias         | **Recomendada**                             |
| 2. React Router em modo framework com `prerender` e `ssr: false`                                                                                                                                             | Solução oficial, mantida pelo React Router, pré-renderização e `meta` por rota prontos                                                                     | Migra o roteamento para o modo framework (plugin `@react-router/dev`, `app/routes.ts`, módulos de rota com vários exports nomeados como `meta`, `loader` e `default`), o que quebra "um símbolo por arquivo" e muda `CLAUDE.md`, skills e testes | 6 a 10 dias        | Descartada na v1; rever na V2+ por ADR      |
| 3. `vite-react-ssg`                                                                                                                                                                                          | Aceita rotas de data router e `getStaticPaths` para os ids                                                                                                 | Projeto de um mantenedor, compatibilidade com Vite 8, React 19 e React Router 7 não garantida; usa `Head` próprio (react-helmet-async), contra a convenção de metadados nativos do React 19                                                      | 2 a 4 dias + risco | Descartada (plano B se o spike de 1 falhar) |
| 4. Snapshot com navegador headless (Puppeteer, `react-snap` e afins)                                                                                                                                         | Nenhuma mudança no código da aplicação                                                                                                                     | Chromium no CI; snapshot do DOM sem hidratação de verdade (o React refaz a árvore); `react-snap` abandonado                                                                                                                                      | 2 a 3 dias         | Descartada                                  |
| 5. Não pré-renderizar; só `llms.txt`, `sitemap.xml` e JSON-LD estático no `index.html`                                                                                                                       | Barato                                                                                                                                                     | A URL que o recrutador cola continua vazia para o fetcher de IA e para a prévia de link; rotas internas seguem respondendo 404 no Pages                                                                                                          | 1 a 2 dias         | Plano B da v1 se #49 não couber             |

Efeito colateral da opção 1 no GitHub Pages: cada rota pública tem arquivo próprio, então responde
**200** na primeira carga; o `404.html` passa a ser a página não encontrada pré-renderizada e só
responde a URL que de fato não existe (substitui a cópia do `index.html` prevista em M4).
